# Confidence Gating for LLM Text-to-SQL — Code & Data Artifact

Artifact for the paper *"When to Execute, Defer, or Abstain: A Fully Audited
Study of Confidence Gating for LLM-Generated SQL"* (anonymous submission).

The paper audits six confidence methods plus a split-conformal wrapper on a
6,000-candidate DeepSeek pool over 300 difficulty-stratified BIRD dev
questions, and adds a strengthened judge suite plus a second-generator
replication (Kimi k2.6, 150 questions x 20 candidates) in a second round.
Headline numbers (AUROC / ECE_15):

| Signal | AUROC | ECE_15 | selEX@30 |
|---|---|---|---|
| B1 verbalized (self) | 0.573 | 0.421 | 0.529 |
| B5 LLM-judge (self) | 0.560 | 0.408 | 0.513 |
| B4 clause recalibration (white-box) | 0.647 | 0.134 | 0.690 |
| fuse_prod (B4 x execution share) | 0.666 | 0.121 | 0.708 |
| B5-strong (Kimi k3, generator-independent) | 0.654 | 0.391 | 0.669 |
| B4 frozen transfer (DS-fit -> Kimi pool) | 0.734 | 0.128 | 0.687 |

Always-execute reference: 0.537. Split-conformal auto-execution fails under
question-level calibration (realized leakage 1.4-1.5x alpha, tail 6.8x) while
being exact under candidate-level splits; the failure direction reproduces on
the second generator (1.70x / 2.70x alpha).

## Reproducing the paper

**Level 1 - all tables/figures from the released pools (no API, no BIRD).**

```bash
python baseline/tools/p0_reanalysis.py     # main comparison, conformal diagnosis
python baseline/tools/p1_analysis.py       # split variance, LODO, difficulty, figures
python baseline/tools/p1_api_analysis.py --part all   # round-2 judges + 2nd generator
```

Each writes a `results/revision_*.md` report plus `results/_*.json` stats and
regenerates `figures/fig_*.pdf`. `baseline/eval/run_eval.py` recomputes any
single method's metrics from `(pool, labels, conf)` triples.

**Level 2 - re-execute labels & regenerate perturbed databases (needs BIRD, no API).**

```bash
python data/scripts/make_schema_drift.py   # rebuild data/schema_drift sqlite copies
python data/scripts/validate_drift.py      # label-flip audit for the VIEW split
python baseline/b2_consistency/run_b2.py --pool data/pools/bird300_ds_pool.jsonl     --out /tmp/b2.jsonl --k 10             # re-executes the sampling groups
```

**Level 3 - full pipeline from scratch (API).**

```bash
python data/scripts/make_pool.py           # candidate pool + labels + logprobs
python baseline/b1_verbalized/run_b1.py --pool data/pools/bird300_ds_pool.jsonl --out ...
python baseline/b5_judge/run_b5_judge.py --pool ... --out ...
python baseline/tools/run_b1_variants.py   # two-stage / top-k elicitation
python baseline/tools/run_b5_cross.py      # cross-/strong-model judges (Kimi k3)
python baseline/tools/run_fuse.py          # fuse_min/prod/stack
python baseline/b8_conformal/run_b8_conformal.py --alpha 0.02
python baseline/tools/run_lodo.py          # leave-one-database-out
python baseline/tools/run_drift.py         # schema-drift judging
python baseline/tools/run_chal_expand.py   # 117-question challenging expansion
```

The B6/B7 questionnaire judge is an internal system without a public
write-up; the zero-shot reproduction protocol is in
`baseline/b6_laya/run_b6_judge.py`, and its DeepSeek-administered verdicts are
released (`data/pools/bird300_ds_b6verdicts.jsonl`). Re-running the original
local-model variants requires the internal exports (not redistributable).

## Cost accounting

The entire study is designed to be cheap enough to rerun end-to-end:
generation + all API evaluations in round 1 totalled ~CNY 23-25 (< US$4);
round 2 (second-generator pool, Kimi self-judging, Kimi k3 strong judge,
DeepSeek cross-judging and elicitation variants) is estimated from prompt
volumes at list prices at ~CNY 60-90 (input-cache discounts not included).
Study total: ~CNY 90-110 (< US$16). Details: `results/revision_api.md`.

## Decoding disclosure

DeepSeek-chat: greedy (T=0) for all judge/elicitation calls; pool generation
at T=0.8 (nucleus, p=0.95) and T=0.2 (low-temperature arm). Kimi k2.6 / k3
(Moonshot): the endpoint only serves non-thinking mode with enforced
T=0.6 / top_p=0.95 / n=1 (`reasoning_effort=none`); disclosed wherever used.
Judge calls that remain unreachable after retries are recorded as a neutral
0.5 fallback (<=2% of candidates); unparseable replies are dropped (<10 per
file). All accounting counts `exec_fail` as wrong.
